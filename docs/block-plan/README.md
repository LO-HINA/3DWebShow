## 3. 编号规则

采用“方位缩写 + 括号内整数”：`NW(0)`、`NW(1)`、`NW(-1)`、`NW(-2)`；正数不写额外加号。

- `NW(0)`：西北区域的弧形基准建筑。
- `NW(-1)`：NW(0) 西侧第一栋；`NW(-2)`：继续向西下一栋。
- `NW(1)`：从 NW(0) 沿东北方向延伸的第一栋。
- 编号不表示高度、规模、功能或重要程度；负号也不是 Three.js 坐标的负号。
- 其他区域的正负编号延伸方向仍待用户确认，不能照抄 NW 的方向。
- 内部字符串、配置表、导视与任务卡必须使用同一标识；文件系统别名不同时应明确映射，不擅自改显示编号。

## 4. 空间与坐标约定

- 沿用工程坐标：`+Y` 向上、`+X` 向东、`+Z` 向南、北为 `-Z`，`1 unit = 1m`。
- 手绘图确定的是道路、转角、前后与相邻关系，不是米制施工图。不能从照片透视或手绘像素直接推定精确尺寸。
- 可把 `M` 作为新布局原点，但这是便于实现的建议，最终落位在量化布局时记录。
- 待定尺寸至少包括：道路宽度、四个转角建筑的占地与弧面半径、楼间距、建筑高度、SCREEN 与 M 的间距、入口与安全站立点。
- 新路口不受旧 64×64 中心地面、旧环路坐标或旧布局版本永久限制。

## 5. 保留的风格与设计边界

**继续保留**：赛博朋克艺术街区、暮光夜景、玻璃与深色结构、霓虹与流动光幕、完整图片展示、湿润反射地面，以及有体量与层次的城市空间。建筑应在远处有清楚轮廓、中距离能读立面构造、近处有入口与材质细节；图片也要有独立完整的展示区域。用灯带、发光矩形和复杂贴图替代建筑形体的做法不符合目标。

**不再作为全街区强制规则**：

- “以低矮暖砂岩 E-01 为全街区样板”。
- “主体高度不超过宽度的 0.6 倍”。
- “固定双塔三馆与北高南低”。

这些只作为旧方案记录。门窗厚度、图片比例、材质分层和运行验收等方法仍然有效；过期的建筑身份与空间分配不再保留。

**可复用但不能自动分配**：

- 媒体楼四面放用户漫画、展位错开高度、其余立面做流动光幕：是此前讨论过的意向；是否整套用于新 `SE(0)`，需逐栋确认。B-01 的 `b01MediaConfig.ts` 可作为“内容与安装构造分离”的工程先例。
- M 的大型双轨、两颗运动球、能量光圈和低矮投影基座：可作为轨道仪候选；旧建议的 8–10m 等数值不是新布局已确认尺寸。
- 轨道仪按交互键进入独立地球/星图页：已提出的方向，可预留 action 与页面接口；本轮不顺带实现完整天文或数据应用。
- SCREEN 的全视口封面、主题滑条、关闭后揭示对应风格：属于已有产品方向，与 M 的内容页入口分开管理。

不自动给 NW / SW 赋予酒店、学习馆或 AI 实验室等用途；风格参考不等于功能设定。未说明的室内也不自动承诺可进入、可爬楼或完整建模。

## 7. 改布局必须同步的工程关系

### 7.1 一栋建筑的统一配置

按实体维护：标识、区域、视觉工厂/资产、世界变换、视觉范围、碰撞代理、媒体插槽、交互点、返回点、观赏点和负责人。可逐步引入字段，不要求一次更换所有公共接口；不要另造一套与现有 `layout / exhibits / colliders` 平行且冲突的注册数据。

### 7.2 曲面建筑与碰撞

当前建筑碰撞主要是按 `BuildingSpec.size` 生成的大盒子，公共类型只有 box 和 cylinder，不足以直接表示留出道路的弧形建筑。`NW(0)` / `SW(0)` 应分别定义实际占地与碰撞：可先用沿曲面排列的少量旋转盒体近似墙体，确有需要再增加凸体支持。视觉包围盒、实体墙与可行走门口分开处理，避免一个大盒子填满凹面或封堵道路。玻璃透明不代表可以穿越；角色碰撞、镜头碰撞、遮挡淡出与媒体展示分别校验。

### 7.3 媒体与建筑分离

漫画/图片配置记录作品 ID、来源路径、宽高、展示模式、槽位与替代文本。每栋楼可有多个插槽，内容不烘焙进不可更换的整楼贴图。默认完整显示、保持原比例；图片区域不被窗格或横梁切割，白底漫画不被强辉光洗掉。流动光幕在独立装饰区域工作，避免覆盖正文和线稿。

现有 `BuildingSpec` 海报类型只支持两个命名槽且位置偏向正面；四面/错层展示若被确认，需要面向不同朝向与数量的插槽配置，不能只复制正面两幅海报并改图片地址。

### 7.4 网格合并与独立修改

`mergeStaticScene` 会把共享材质网格变换到世界坐标后合并，原网格脱离建筑父节点；合并后只移动建筑 Group 可能让窗框等留在旧位置。首轮可通过修改配置后完整重建场景保持一致。需要独立替换或动态变换的建筑、媒体、光幕、玻璃、M 的轨道和运动球，应保留独立容器与合并排除规则。`merge.ts` 的属性归一化目前只保留 position/normal/uv；接入依赖额外属性资产前先调整合并适配。

### 7.5 交互、目录与返回点

搬动建筑时同时更新媒体观看位置、入口交互点、前向、传送点、页面返回点和目录文案；建筑中心不能代替门前可站立点。给 M 添加交互入口时必须处理当前 `V` 的“仰望高楼”绑定，同一次按键只能分发一个有效动作；M 与 SCREEN 分别拥有动作，不混用地球页入口与世界风格选择。新增装置或内容页时按实际动作扩展公共契约，并同步 HUD/手机触控，不在模型工厂里注册全局按键。

### 7.6 快照与布局版本

新路口使用新的 `layoutVersion`；已有“版本不匹配即拒绝旧快照”的逻辑可复用，让角色回到新出生安全点，无需为此实现完整多世界会话。旧坐标确实安全时才迁移；没有明确 ID 对应关系时，不根据旧建筑编号猜测新门口。恢复后清空移动输入并重新检查角色与镜头位置。

## 11. 验收要求

**布局与建筑**

- 俯视图中道路、四个转角、M、SCREEN 与手绘关系一致，标注 N/E/S/W 和新编号。
- 每栋检查路口视角、正面、侧前方与背面；近景不暴露未处理的大空白墙或仅正面完整的舞台布景。
- 图片完整、方向正确、可辨识，普通行走与合理观赏位置均可发现；需要细读时有灯箱或后续指定的查看方式。
- 曲面方向正确，门口与相邻通路可达；M 的运动包络不穿楼、不侵占必要站立点。
- SCREEN 与 M 分别有可读轮廓，默认视角不让中央装置遮住大屏主要画面。

**连续操作**

- 持续贴墙行走、绕过直角/弧面、快速拖动镜头、近地仰视后继续走，角色与相机保持有效跟随。
- 相机靠近角色时淡出与恢复正常；不能靠限制仰视或把镜头锁高来隐藏问题。
- 打开灯箱/目录/页面后停止世界输入，关闭后恢复；输入法和表单不触发快捷键。
- 刷新、浏览器后退、直接访问内容页以及旧快照恢复均有安全落点。

**性能与媒体**

沿用画质分档，逐项记录真实开销。旧规范的 150 calls / 150k 三角面等是历史目标，不是本轮已测结果；不按旧单栋极低面数目标机械削平新建筑。高画质可试验湿地反射与辉光，低画质维持展示可读。光轨、光幕、漫画和玻璃一并检查亮度、深度、透明排序与阴影。记录实际设备、分辨率、DPR、画质、机位、calls/triangles 和帧耗，不直接比较不同截图上的 FPS。
