## 第二轮：减轻立面的贴图感

用户再次指出建筑缺少细节。本轮对照 [Neon Zenith 的 facade kit 实现](https://github.com/billpwchan/neon-zenith/blob/main/src/city/facadekit.js)：上游近处使用 GLB 立面单元，按单元和 LOD 实例化，并非只在平墙上显示窗格。本工程借鉴构造层次，自行生成几何，没有下载上游模型或立面图片。

同时复核了 [Threejs Conference 的湿地面实现](https://github.com/ektogamat/threejs-conference/blob/main/src/world/ground/createGround.js)和 [Samsy 重建项目的工程说明](https://github.com/boyang-hu/samsyninja-rebuild)。前者将平面反射与地面材质结合；后者描述了实例化 kit 和烘焙氛围体系，属于重建者的说明，不能作为本工程效果或原站性能的独立验证。本轮保留已有地面、灯光与后期，仅修改建筑立面生成器。

- 开间从约 1.65m 调至约 2.15m，减少密集的小亮格；普通楼后墙相对原立面的内退目标从 0.78m 增至 1.35m，玻璃后退到约 0.46m。核心同步内退，避免穿进新房间。
- 补充厚窗间墩、外窗台及滴水边、楼板边、遮阳板与支架。T-01/B-01 强调竖肋，T-02/H-01 强调横向遮阳，三个展馆/终端使用盒式构件。
- 侧背面布置确定性分布的设备舱，百叶为倾斜实体叶片与空隙；部分亮窗增加隔墙和半拉窗帘。T-03 省去近景支架及家具，控制高楼细节成本。
- 暖/冷房间背板发光强度从 0.98/0.90 降至 0.32/0.28，不再纳入辉光；小型顶灯保留亮点，避免整片窗背板成为发光方块。
- 新外部构件相对现有各体量外表面最多伸出约 5cm，没有增加阳台、台阶或改动通路碰撞。

`geometry-checks.json` 新增正视/斜视射线检查：正视命中房间后墙，斜视先命中实体窗框；同时检查实例矩阵有限、媒体槽保留及房间背板不进入辉光。它证明几何遮挡关系，不是运行截图。类型、依赖边界、原生预览打包均通过。Playwright 本轮仍在驱动启动阶段遇到 WinError 5，没有产生截图或视频；实际视觉与 GPU 性能仍未验收。

## 窗户构造与性能策略

外壳核心向内退让，外侧使用窗间墙、实体竖梃/横框、窗洞侧壁、地板、顶面和后墙构成真实空腔。第二轮玻璃面后退约 0.46m；近中景房间进深约 1.35m，独立媒体塔约 1.1m。亮灯房间包含实体顶灯，近景还放置桌面和屏幕体块。新窗材料没有图片贴图，也没有用室内映射替代这些房间。

窗光按建筑、楼层和租户区段确定性分布。框体和房间按材质实例化，当前建筑检查场景合计 22,414 个实例、约 295,180 三角面（含不可见代理）；比上一轮增加约 21% 三角面，实际帧耗尚未测量。有限顶点与几何规模见检查 JSON，不将其当作 GPU 帧耗。原外壳保留为不可见、禁止合并的遮挡查询代理，避免角色遮挡检测逐个遍历全部窗框。

原坐标、朝向、入口交互、内容路由、媒体通道、相机、10m/s 普通移动、无冲刺及跳跃保留。碰撞配置未变，窗后空间为视觉室内，不新增可穿入的物理房间。

## 光影接入

正式场景沿用 WebGL2，保留现有媒体塔 GLSL；独立 WebGPU/TSL 样板仍单独存在，没有宣称全城已迁移。冷色主光、较低环境填充、暖补光与分区室内光共同调整。

辉光先按发光材质选择遮罩，再进行低分辨率 Bloom；普通白字和亮墙不会仅因亮度阈值整面泛光。遮罩渲染后恢复材质、背景、雾与阴影更新状态。最终通过 OutputPass 进行一次输出转换。

共享一套平面反射，写入广场、步道与外围地面材质。旧局部镜面停止重复渲染；反射时使用黑色占位采样，避免读取正在写入的反射目标。反射长边上限 768px、按画布约 40% 起调；湿区、干区和掠射角共同调节强度。辉光通道约为半分辨率。流畅模式直出基础画面，后期和反射目标缩到 1×1。

这些是工程实现与初值，不代表已在实际 GPU 上验收。需要继续检查转角玻璃排序、窗后空间遮挡、反射亮度、辉光范围和帧耗。

### 立面参数位置与含义

参数当前直接位于 [`cityStyle.ts`](../../src/worlds/cyberpunk/buildings/cityStyle.ts)，不是设置面板或外部 JSON。改动该文件影响八栋建筑；素材地址继续由原媒体清单和各内容槽管理。

| 参数 / 构件 | 普通楼 | T-03 简化配置 | 调整时要检查 |
| --- | --- | --- | --- |
| `stats.depth` / 后墙内退目标 | 1.35m | 1.1m | 从原体量外表面量起；每体量还受最短边一半减 0.12m 的限制 |
| 玻璃内退 | 0.46m | 0.46m | 与窗框、窗帘、后墙的次序及透明排序 |
| 目标开间 / 层高 | 2.15m / 3.15m | 3.8m / 5.5m | 实际按体量宽高取整分配，不是精确等距的强制规范 |
| `profile` | 依 variant 选择竖向 / 横向 / 盒式 | 默认横向 | 由 `applyCityStyle()` 分配；不能据此改变主楼布局或媒体槽 |
| 玻璃材质透明度 | 0.09 | 0.09 | 过高会遮住室内，过低会削弱玻璃层次；须转角检查 |
| 暖 / 冷背板发光 | 0.32 / 0.28 | 同左 | 不在辉光选择中；顶灯强度 1.9，独立保留辉光 |
| 百叶舱 | 侧背面选定开间，9 片实体叶片 | 每舱 6 片 | 倾角约 -0.42rad；不占用正面媒体和门口预留区 |
| 小支架、桌面、隔墙与窗帘 | 按构件与亮窗条件生成 | 省略近景支架和室内家具 | 不给高楼全部窗口堆叠近景小件 |

文中的“1.35m / 1.1m 进深”指从原立面到后墙的目标内退距离，不是玻璃之后的室内净深。按玻璃位置计算，二者约剩 0.89m / 0.64m，窄体量还会缩短；不要在后续交付中写成完整可进入房间的净尺寸。外壳核心同步内退，遮挡代理仍沿用原体量。

`far` 是生成时传入的固定标志；没有依据相机距离自动替换实例的 LOD。`FacadeStats.depth` 也是目标参数，不能代替逐窗实测尺寸。调房间深度时同步检查核心内退、侧墙、顶面、窗帘与家具的位置，避免只改一个数值导致互相穿插。

### 可复现的检查命令

在项目根目录的 PowerShell 中执行。以下命令会更新评审 JSON，不会生成真实浏览器截图：

```powershell
npm run typecheck
node scripts/check-dependencies.mjs
foreach ($checkName in @('city-style', 'city-look')) {
  & '.\node_modules\@esbuild\win32-x64\esbuild.exe' "scripts/check-$checkName.ts" --bundle --platform=node --format=esm --packages=external "--outfile=.camera-preview/check-$checkName.mjs"
  if ($LASTEXITCODE -ne 0) { throw '检查脚本打包失败' }
  node ".camera-preview/check-$checkName.mjs"
  if ($LASTEXITCODE -ne 0) { throw '检查失败' }
}
```

常规启动用 `npm run dev`，生产检查用 `npm run build`。当前机器的 5173 曾使用本地原生 esbuild 静态预览以绕开 Vite 子进程启动失败；它不带热更新，不构成生产构建已通过的证据，也不是其他机器必须采用的启动方案。浏览器采集需要先有服务，再执行 `python scripts/capture-city-style.py`；权限问题未解决前，重跑不能被记录成采集完成。
