## 当前实施状态（2026-10-23 第二轮细化）

下文 §0–2 是改造前诊断，不能继续作为“当前没有立面模块、没有 Bloom、没有反射”的判断依据。当前实现以 [城市建筑实施记录](city-style-review/README.md) 和 [`AGENTS.md` §0.1a](../AGENTS.md) 为准；§4 的历史建议与实施状态分开阅读。

第二轮已在 `buildings/cityStyle.ts` 加入竖肋、遮阳构件、盒式窗框、厚窗台、楼板边和实体百叶。普通楼目标房间进深约 1.35m，T-03 约 1.1m；房间背板发光降低且退出辉光。几何检查记录为 22,414 个实例、295,180 三角面，包含不可见代理，不是整场景可见面数或 GPU 帧耗。

本轮核对 [Neon Zenith 的近景 facade kit](https://github.com/billpwchan/neon-zenith/blob/main/src/city/facadekit.js)，借鉴真实立面单元与实例化分工，没有引入其模型和立面图片。本地代码使用程序化几何，不等同于上游 GLB kit、TSL 材质或动态 LOD 的完整实现。`far` 仍是构建时的简化参数，尚无随观察距离切换的立面 LOD。

主场景仍为 WebGL2，独立样板使用 WebGPU/TSL。正视/斜视射线检查能证明几何遮挡关系；城市八栋采集脚本的记录为驱动启动失败。B-01 另有固定机位截图，但不能外推为八栋细化已通过。环境、任务和证据的区分见 [接手说明](CURRENT_TASK.md)，不能据此宣称贴图感已消除或全城画质已验收。

## 0. 结论摘要（改造前诊断）

改造前建筑“差强人意”，不是配色选错，而是三件事没做到：

1. **立面没有语法**：塔楼正面是一整块砂岩盒子，只有 4 扇小窗、3 根鳍片和 2 条灯带。近看是墙，不是建筑。
2. **细节层级倒置**：E-01 把细节集中在入口；塔楼、学习馆、终端亭的上半部几乎全空。玩家平视时看到的恰好是空白墙。
3. **光没有形成“场”**：发光只做细线，且渲染器没有 Bloom/调色后处理；霓虹在画面上只是彩色塑料条。照明又由半球光和大面积环境光托平，立面缺少明暗分区。

初次诊断时，本项目仍是 WebGL2（three r186）直接渲染，尚无后处理管线；直接搬入 WebGPU/TSL 实现会牵动渲染器。当前已接入共享反射和辉光，并有独立 WebGPU/TSL 样板；允许单独验证迁移，不能把当时的实现状态解释成永久禁止更换技术路线。

## 2. 现状诊断：为什么看起来差强人意

### 2.1 立面留白过多，尺度失控

以 `towerA` 为例（`buildings.ts:217-299`）：

- 正立面约 **9.6m 宽 × 15.1m 高 ≈ 145m²**。
- 玻璃窗只有 4 扇，单扇 0.94 × 1.42m，合计约 **5.3m²，开窗率约 3.7%**。
- 其余细节：3 根鳍片（宽 0.2m）、2 条横向凹槽、1 个门洞。正面没有窗格、层间线、阳台、设备或分缝。

参考图里的香港楼宇开窗率大致在 20%–35%，并且每扇窗都有独立明暗。3.7% 的墙在任何光照下都只会是一块平整色块。

### 2.2 细节层级倒置

- E-01 `gallery()` 有墙垛拆分、真实门洞、六层入口、铜框、窗台、灯槽、背面服务门、屋面设备，约 25+ draw calls（`buildings.ts:427-786`）。
- `towerA/B` 的入口只有“背板 + 玻璃 + 三条发光边 + 雨棚 + 两根拉杆”（`buildings.ts:271-280`）。
- `learning()` 和 `terminal()` 更少：一个门洞、招牌、少量窗（`buildings.ts:788-945`）。

结果是：**离玩家最近、占据画面最大的塔楼，细节反而最少**。E-01 的精修没有推广到同世界其他建筑。

### 2.3 体量语法单一

- T-01 与 T-02 都是“主体盒子 + 一个偏心小盒子 + 压顶”；上层偏移只有 0.6–0.7m，高度差 3m。
- 屋面只有 1–2 个设备盒、1 根天线。
- 没有退台层级、悬挑、天桥、核心筒加翼、开放冠顶等可读的轮廓差异。

玩家在广场环视时，看到的是同一栋楼的缩放副本，剪影无法区分。

### 2.4 材质只有“一种砂岩 + 噪声”

`materials.ts:74-97`：

- `concreteWarm`：`#8c7a6b`、roughness 0.85、metalness 0，仅 `bumpMap = noise`、`bumpScale = 0.018`。
- 噪声纹理 repeat 4×10，贴到 10m × 15m 的面上，单个 tile 约 2.5m × 1.5m；0.018 的 bump 在 15–20m 观看距离基本不可见。
- 没有 `roughnessMap`、`normalMap`、`aoMap`、分缝纹理或污渍/雨痕变化。

所以砂岩、浅砂岩、深炭灰在画面上几乎只靠明度区分，缺少粗糙度、法线和污渍带来的“材料感”。

### 2.5 发光没有形成“光场”

- 规范要求“发光只做线和小面”，实现成了每面墙 2–3 条细灯带。
- 细线本身没错，但**数量太少、分布太均匀**；没有招牌、窗光、橱窗、设备指示灯组成的密集小光源。
- 渲染器直接 `renderer.render(scene, camera)`（`WorldEngine.ts:678`），**没有 Bloom、没有调色、没有暗角**；`toneMapping` 只有 ACES + exposure 1.22。

参考站里霓虹之所以“亮”，是因为大量小发光体 + Bloom + 湿地面反射共同形成光场；本项目的灯带没有这层增益，看起来就是彩色塑料条。

### 2.6 照明平坦，缺少色温分区

`WorldEngine.ts:369-425`：

- HemisphereLight 1.35 + AmbientLight 0.72 把阴影托得很平。
- 南侧暖色补光只有 0.42；月光 2.0 从北面来。
- 只有广场、E-01、E-02、E-03 共 7 个点光；塔楼立面本身没有局部洗墙光。

结果：近处立面由环境光均摊，既没有冷色月光面，也没有暖色橱窗面，**明暗对比和冷暖对比都不足**。

### 2.7 街道层密度不足

广场 24m 宽，周边只有 5 栋主楼、5 个画框、长椅、花池和路灯。缺少：

- 底层商铺、雨棚、卷帘门、招牌；
- 空调外机、管道、线缆、配电箱、通风口；
- 售卖机、垃圾桶、货箱、堆叠杂物；
- 入口台阶、门槛、地脚灯。

在第三人称平视机位里，视线高度 1.6m 左右，恰好扫过这些缺失的 0–4m 带。远处再精致也无法弥补近处空旷。

### 2.8 规范与实现脱节

- `AGENTS.md` §1.4 要求 recipe 驱动、体块 2–3 个、退台/悬挑、4m 层高、0.08m 灯槽等；实际 `buildings.ts` 没有 recipe 类型，也没有共享的立面模块。
- `docs/E01_STYLE_GUIDE.md` §2 的“主体高度不超过宽度 0.6 倍”只适用于展馆；塔楼没有对应规则。
- 因此每次修改都是逐个函数手调，无法保证同世界语言一致。

### 2.9 大型屏幕与海报没有进入建筑立面

当前不是“屏幕数量不够”，而是**尺度层级缺失**：

- T-01 / T-02 每栋只有两张海报，画面 3.15 × 5.6m、铜框 3.62 × 6.08m（`buildings.ts:164-205`），挂在 10 × 24m / 11 × 26m 塔楼上，仍是“展馆挂画”。
- T-03 有 26 × 42m 霓虹屏、26 × 30m 视频屏、26 × 18m 图片屏（`mediaTower.ts:28-30`），但塔在 `(44, -38)`，出生机位约 40°–45°，主要屏面中心在 43–107m 高；它读成远景天际线，没有进入广场主构图。
- 广场 SCREEN-01 只有 8 × 4.5m，下沿 2.6m（`layout.ts:7-11`）；12m / 14m 方案仍停在提案，没有替换正式场景。
- 画框 W1–W5 与 E-01 竖向海报是 1–3m 级信息物，不能承担“城市媒体”的视觉重量。

结果：玩家的第一眼是“画廊 + 一块屏”，而不是“建筑本身在发光、在传播内容”。建筑媒体立面应作为独立层级进入设计，而不是把现有海报整体放大。

## 3. 参考站拆解

### 3.1 Neon Zenith（霓虹天頂）

**它做了什么**

- 9,373 栋建筑、3.2km 网格的连续城市；远景不是天空盒。
- **建筑语法**：办公塔有退台、堆叠悬挑、双塔天桥、鳍片板楼、核心筒+翼五种形制；每栋再从四种冠顶里选一种（开放框架 + LED 环梁、发光鼓体、阶梯顶、设备房 + 檐口）。住宅有十字形、H 形、板楼。
- **三级立面**：
  - <180m：建模立面套件（凹窗、窗框、空调、格栅），实例化 + LOD；
  - 任意距离：实拍式立面纹理数组，每扇窗有独立房间视差、家具、窗帘、亮/暗状态；
  - 塔楼：解析式幕墙着色器，每栋自己的开间、层高、玻璃比例、玻璃色、窗间墙色；办公室按租户成片亮灯。
- **街道光图**：2048² 顶视街灯图覆盖 3.5km，道路、立面、雨、雾、云底共同采样；成千上万霓虹只花一次纹理读取。
- **招牌系统**：约 390 块 LED 屏，16 个虚构广告活动用 Canvas 绘制，无图片文件；换页、故障、近看可见 LED 点阵。
- **后期**：Bloom → 调色 → ACES → 色差 → 暗角 → FXAA → 颗粒。
- **手工街区**：Blender 逐铺搭建 + Cycles 烘焙 4096² 光照贴图（10–14 px/m）。

**可迁移到 LOHINA 的原则**

1. **立面先是语法，再是贴图**：每栋楼配置开间宽度、层高、开窗率、玻璃色、窗间墙色；窗格、层线、竖梃由参数生成，而不是手摆几个盒子。
2. **每扇窗有自己的明暗**：用 seeded random 决定亮/暗、暖/冷、是否拉帘；办公室按“楼层 + 租户区段”成片亮，避免整面墙均匀发光。
3. **体量与冠顶分离**：先选形制（退台/悬挑/双塔/鳍片/核心+翼），再选冠顶（框架/鼓体/阶梯/设备房）；剪影差异由数据保证。
4. **街道光图替代大量点光**：用一张局部顶视光图给立面、地面、雾着色，比每栋楼放点光便宜且统一。
5. **招牌是城市内容**：把招牌当作可换页的“广告活动”，而不是静态贴图；至少让近景招牌有 2–3 种状态。

**不要照搬**

- WebGPU + TSL 渲染路径与 130MB 资产管线；本项目不为此重写。
- 9,373 栋的密度与香港峡谷尺度；LOHINA 的“暮光新野兽派”需要保留广场负空间。
- Blender 手工街区 + 4K 烘焙流程；当前没有该制作资源。

### 3.2 Threejs-Punk（ektogamat/threejs-conference）

**它做了什么**

- 雨夜赛博小巷：密集霓虹招牌、湿地面、GPU 雨（尊重屋顶与道具高度）、体积感雾。
- **后期是“look preset”**：Bloom、景深、色差、暗角、调色打包成一套可切换的赛博观感。
- 地面湿反射 + 雨滴波纹 + 车灯拖影；材质与光照围绕“湿、亮、脏”组织。
- 第一人称 BVH 碰撞漫游；自适应 DPR、着色器预热。
- 大量视频广告牌与管线、电缆、纸箱等街道杂物构成近景密度。

**可迁移到 LOHINA 的原则**

1. **先定一套“观感预设”**：曝光、Bloom 阈值/强度、色彩分级、暗角作为一个整体调，不要逐项加特效。
2. **湿地面是氛围的一半**：广场/步道用低分辨率平面反射或镜像发光片，优先让招牌和灯带在地面留下颜色。
3. **近景密度靠“杂物层”**：管线、电缆、空调、货箱、垃圾桶、蒸汽，比再增加一栋楼更能提升真实感。
4. **招牌分层升级为建筑媒体立面**：远景天际线屏 / 中景整面媒体墙与竖向巨幅 / 近景小店灯箱，三种尺度和亮度同时存在；屏幕要嵌入建筑结构，不能浮贴。

**不要照搬**

- 全屏 TSL 后处理管线与 WebGPU 依赖；本项目可先用 three addons 的 `EffectComposer + UnrealBloomPass + OutputPass` 验证。
- 雨、景深、色差同时全开；移动端和低画质档需要能整体关闭。
- 过饱和的全屏紫 / 品红；当前方向是深色壳 + 青 / 品红 / 琥珀高亮霓虹，主色可按街区选择，不强制只保留琥珀 + 青。参考的是对比与密度，不是把整屏染成一个色相。

### 3.3 Samsy 逆向复刻（boyang-hu/samsyninja-rebuild）

> 这是对 AGENTS.md 已登记的 Samsy / `samsy.ninja` 的**逐行逆向研究**，不是可直接引用的素材库。  
> 仓库没有 LICENSE 文件，默认保留所有权利；其 `mirror/` 与 `src/public/` 中的模型、贴图、视频、音频、字体均归 Samsy 所有，README 明确“仅供个人学习研究”。**只读其技术笔记，不复制代码、资产或页面结构。**

**它揭示的观感结构**

- 全站**零实时光源**，应用侧材质基本是 `MeshBasicNodeMaterial`；建筑外观靠烘焙贴图，而不是 PBR 打光。
- 城市非屏幕材质只有一行体积处理：`rgb *= 0.3 * smoothstep(0, 20, positionWorld.y)`——用垂直亮度梯度把盒子读成“有高度的城市”，而不是一面均匀的墙。
- 屏幕材质单独走 CRT 链：RGB 三通道错位采样 → 滚动扫描带 → 竖条纹遮罩 → 按 z 分组随机熄灭 → 8 单位外硬切 LOD；其 emissive 经过雾进入 Bloom。
- 后处理：`MRT { output, emissive }` → `BloomNode`（5 级 mip、HalfFloat、threshold 0.5、运行强度 0.34、radius 0.27×DPR）→ 合成（故障、screen blend、水平暗角、暗部抬升、CRT 扫描线）。**Bloom 只吃 emissive，不吃被照亮的墙面。**
- 湿地面：`colorNode` 纯黑，`emissive = reflector(0.75) × 法线扰动(±0.01) × 双频遮罩 × 0.6`，再被 Bloom 吃成霓虹倒影。
- 氛围：黑色距离雾（IDLE 700/800，WORKS 150/170）负责纵深；`toneMapping` 保持 `NoToneMapping`，靠 emissive 强度和后处理控制明暗。
- 城市规模：`cyberfix.glb` 只有 **16 种 kit 件、35 处摆放**，密度来自重复、招牌、灯光与镜头，而不是独特几何数量。
- 性能：像素预算上限 3500×1800、DPR ≤ 2、实例化 + 32 位 4 趟基数排序做透明排序、CPU 粒子 + GPU instancing、无 GPU compute。

**可直接借鉴的原则**

1. **把“观感”当成合成配方，而不是打光配方**：黑雾 + 烘焙/程序化 albedo + 仅 emissive 进 Bloom + 暗部抬升 + 暗角。LOHINA 可保留暖色 PBR 基底，但把霓虹亮度从“材质颜色”转移到“emissive 掩码 + Bloom”。
2. **垂直线性明暗梯度**是极便宜的体积线索：箱体建筑加一层 `y` 方向亮度渐变，就能摆脱“纸片墙”。
3. **Bloom 阈值与 MRT**：如果实现后处理，优先只让招牌、窗光、屏幕进入 Bloom，避免整面砂岩一起发光。Samsy 的 threshold 0.5 / strength 0.34 / radius 0.27 是可参考的起点，不是固定值。
4. **模块化 kit**：16 件 × 35 摆位即可成城；LOHINA 可以把“商铺门面、窗格、雨棚、屋顶设备、招牌”做成可复用 kit，而不是每栋楼重写。
5. **屏幕链只用在该用的地方**：媒体塔、广场大屏可有轻微扫描线/色差/熄灭；不要把 CRT 效果铺满整个画面。
6. **像素级验收方法**：该仓库用“同侧自比带宽 + 残差归类”比较截图，而不是单值相似度。LOHINA 的固定机位前后对比可借用这个思路：先测同一版本多次截图的波动，再判断改动是否越界。

**不要照搬**

- 代码与资产：无许可证，且素材归 Samsy 所有；只能阅读其 `docs/engine-notes.md` 的设计结论，不能拷贝实现。
- 零光照 + 全 unlit 的艺术方向：它适合纯霓虹夜景；LOHINA 的深色城市壳仍需要基础方向光 / 环境光或烘焙贴图来维持入口可读；可以叠加，不要替换。
- CRT、故障、扫描线作为全屏身份：那是 Samsy 的视觉签名，整套搬来会变成模仿。
- WebGPU/TSL、双 three 拷贝、VAT 骨骼管线：与本项目当前任务无关。

### 3.4 建筑媒体立面：从“一块屏”到“媒体建筑”

Neon Zenith 的约 390 块 LED 屏、Threejs-Punk 的远/中/近三层招牌、Samsy 的少数装饰大屏，共同说明：**屏幕的说服力来自它与建筑尺度的关系，不来自单块尺寸。** 本项目应把大型媒体当作建筑立面类型，而不是广场装置。

| 层级 | 典型尺寸 | 作用 | 本项目落点 |
| --- | --- | --- | --- |
| 天际线媒体 | 20–30m 宽，或 80m 以上塔身 | 远景地标、抬头可见 | T-03 保留 26m 级主屏；先验证可见性，不盲目再加 |
| 屋顶广告牌 / 天际线屏 | 10–16m 宽 × 5–8m 高 | 广场抬头可见，补天际线 | T-01 屋顶候选 12 × 6m，独立钢架；与 T-01 竖幅二选一 |
| 整面媒体幕墙 | 8–10m 宽 × 18–22m 高，占可见立面 30%–50% | 一栋楼一个主视觉 | T-02 品牌塔南立面 8.4 × 20m |
| 竖向巨幅 / 灯箱 | 4–5m 宽 × 12–18m 高，可双联 | 中景楼体广告 | T-01 南立面两块 4.2 × 9.5m |
| 裙楼 / 转角色带 | 12–18m 长 × 3–4m 高 | 街道层内容与光带 | E-03 AI 终端亭两个可见面；亭体仅 5m 高，色带压到约 2.2m |
| 街面小灯箱 / 画框 | 0.6–3m | 近景信息、入口导视 | E-01 门头、橱窗、0.66 × 1.32m 海报 |

**构造原则**

- 屏体凹入墙面 0.3–0.5m，四周 0.15–0.25m 边框或回壁；不能零厚度浮贴。
- 结构竖梃 / 水平梁从屏前跨过，每 3–4m 一道；屏幕边缘对齐 4m 层高与结构开间。
- 主屏下沿原则上 ≥3.5m；裙楼 / 转角色带按实际层高压低，但不低于 2.2m。下部做检修马道、线槽、通风格栅或雨棚；顶部留散热和维护空间。
- 一张立面最多一个主屏；相邻建筑不要复制同一尺寸与构图；至少保留一栋暗立面（E-01）。
- 屏幕内容 2–3 套原创活动轮换，保留 20%–30% 暗部；不使用真实品牌或未授权素材。
- 屏幕是发光体，不是照明灯：颜色溢到边框、墙根和湿地面，但不以新增 PointLight 代替自发光。

**性能与构图**

- 核心街区首轮最多 3 块大屏 + 2 块中型屏；同时播放视频不超过 1 路，其余静态或定时换页。
- 单屏纹理 1024–2048 宽起调；共享材质与几何；反射层只收屏幕 / 霓虹，不把整座城市送入反射。
- 出生机位应同时读到左侧竖向媒体、右侧整面媒体墙、中央广场端点屏；T-03 作为远景 / 抬头地标。
- 单栋可见立面媒体面积 30%–50%；小于 15% 仍是“挂画”，大于 60% 是“整栋电视”，两者都要复核。

实施细节和验收项以 `AGENTS.md` §1.1a 为准；本节只记录参考结论，不授权代码修改。

### 3.5 V4.0 Samsy 夜景报告：可采纳机制与参数修正

> 用户在 2026-10-23 提供的 V4.0 报告主张“1:1 复刻”黑曜石暗夜、全息灯箱森林、CRT 黑镜；未入库，也不是施工单。  
> 它与 §3.3 观察的是同一参考站，但 §3.3 是技术笔记，V4 是视觉提案；本节只记录可迁移机制和必须修正的参数。

**方向为什么成立**

V4 抓对的不是某个 Shader，而是构图关系：

- 建筑退成黑剪影，不再用墙面细节抢画面；
- 发光面按近景作品巨幕、中景机能字牌、远景徽标矩阵分层；
- 地面接近纯黑，只让上方霓虹形成高对比倒影；
- 前景角色用逆光和红色光弧压住画面，避免只有发光牌子。

这套关系和用户要的“高亮霓虹 + 地面镜面反交相辉映”一致。但截图冲击力来自**黑负空间 + 发光密度 + 倒影 + 前景剪影**的组合，不是单独一个 CRT 或 Bloom。

**V4 评审时的构建事实（2026-10-23，其后已变）**

- 评审当时 `WorldEngine.ts` 仍是直接 `renderer.render(scene, camera)`；现已由 `engine/core/cityLook.ts` 在 HIGH 画质接入 `EffectComposer`、选择性 `UnrealBloomPass` 与 `OutputPass`，SMOOTH 仍直出。是否达到 V4 的黑剪影构图仍需真实 GPU 验收。
- 色调映射为 `ACESFilmicToneMapping`，曝光 1.22；雾为线性 `Fog(PALETTE.fogColor, 90, 580)`。这两项当前未改。
- 场景已有 7 盏点光、月光和 PBR 道具（B-01 另有局部灯）；V4 若一边保留这些灯、一边用近纯黑 `MeshStandardMaterial`，黑墙会被局部照亮，剪影不成立。要么走 unlit / 烘焙路线，要么保留 PBR 但把壳体压暗、只让屏幕和霓虹发光。

**机制拆分**

| V4 做法 | 结论 | 修正 |
| --- | --- | --- |
| 黑剪影壳体、三层灯箱、黑镜地面、角色逆光 | 采纳为 look preset 候选 | 不改 §1.1 基线；不覆盖 E-01；Bloom 关闭时仍须成立 |
| `FogExp2(0x030306, 0.022)` | 不采纳 | 对当前 60–128m 场景过浓：约 60m 透射率 18%，100m 不到 1%，会吞掉 T-03；从 0.006–0.010 起调，或改高度雾 / 线性雾，固定机位验证 |
| 全楼 `MeshStandardMaterial` + `metalness 0.85` + `EdgesGeometry` | 不采纳为统一做法 | 无环境贴图时金属黑墙接近纯黑；逐栋线框增加 DC、锯齿和 CAD 感。Samsy 实际是 unlit / 烘焙 + 垂直亮度梯度；线框只用于重点体块 |
| 15–25 张独立发光平面 | 改造后采纳 | 1024² × 15 约 60MB，2048² × 15 约 240MB，另有透明 overdraw 与排序；用图集、合并几何、LOD；核心视锥 8–12 张机能贴片 + 3 大 + 2 中主屏 |
| `NeonBillboardShader` | 改造后采纳 | 必须补雾、tone mapping、色彩空间、宽高比与 alpha 边缘；裸 `ShaderMaterial` 不会自动获得场景的远景衰减和输出转换 |
| threshold-only Bloom + CRT | 改造后采纳 | Bloom 用选择性 emissive / MRT，不让天空和白字整体发光；CRT 暗角 `smoothstep(0.95, 0.28, dist)` 的 edge 顺序反了，改为 `1.0 - smoothstep(0.28, 0.95, dist)`；扫描线按固定线数或 CSS 像素，提供关闭与减少动态 |
| `Reflector` 上叠 0.45 透明黑面 | 改造后采纳 | 透明排序、深度写入、阴影片和反射层容易冲突；在一个地面材质里合成反射、水洼遮罩、法线和粗糙度，只让屏幕 / 霓虹进入反射层 |
| 全红 HUD、`Frame: 2.8 ms`、`WebGPU` 标识 | 部分采纳 / 不采纳 | 红色只作强调，状态仍需文字或图形；帧时间必须真实测量，不能写死；当前是 WebGL2，不得标 WebGPU |
| “1:1 复刻 Samsy” | 不采纳 | 无许可证、素材归 Samsy 所有；只借机制，重新设计构图、内容、HUD 与视觉签名 |
| 整体重写场景 / 替换全部 UI | 不采纳 | 单独 lookdev spike；保留 E-01、`mediaTower.ts`、`media.ts`、广场屏与未提交资产 |

**首轮建议参数**

- 雾：`FogExp2` 密度从 0.006–0.010 起调，或保留线性雾 90–580；先在出生、抬头、走近三个机位确认 T-03 主屏仍可读。
- 发光面：8–12 张机能贴片 + 3 大 + 2 中主屏；小贴片用 1024² 图集，主屏 2048² 起调；同材质合并，远景切 LOD。
- 地面：单平面反射，纹理从 256–512 起调，限制反射层；不要先叠透明黑面，再靠“半分辨率”宣称性能。
- Bloom：threshold 只作实验起点，必须加选择性 emissive / MRT 或等价排除；天空、白字、亮墙不得整体发光。
- CRT：默认轻量、可关闭；扫描线按固定线数或 CSS 像素，不按物理分辨率；`prefers-reduced-motion` 下关闭或降强度。
- HUD：红色作为强调色，保留真实性能数据；没有测量就不显示帧时间，不标 WebGPU。

**验收**

- [ ] 固定机位记录 Bloom / CRT 开与关、反射开与关；黑剪影在 Bloom 关闭时仍成立。
- [ ] 雾不吞 T-03 主屏；出生、抬头、走近三个机位都能读到至少两种媒体尺度。
- [ ] 不出现 15–25 张独立贴图、全城 EdgesGeometry、写死帧时间或 WebGPU 标识。
- [ ] E-01 仍保留暗面留白和入口可读性；V4 预设不默认覆盖 E-01。
- [ ] 记录 DC、三角面、纹理、反射 pass 与帧耗；不达标回退参数，不靠提高曝光补救。

## 5. 视觉验收指标（建议写入任务验收）

- **开窗率**：中近景塔楼正立面 18%–30%；展馆 12%–25%。
- **开间/层高**：开间 1.6–2.4m，层高 3.6–4.2m；同一栋楼内一致，不同楼可不同。
- **剪影**：初始机位内至少 3 种不同形制、2 种不同冠顶可辨。
- **街道层**：沿建筑立面每 6–10m 至少一个可读细节簇（门、窗、招牌、设备、管线之一）。
- **发光面积**：单面墙发光面积 10%–25%，以招牌 / 窗光 / 屏幕为主，不要求整墙发光；Bloom 关闭时材质与门洞暗部仍成立。
- **建筑媒体立面**：核心街区首轮 3 块大屏 + 2 块中型屏；每栋最多 1 个主屏；单栋可见立面媒体面积 30%–50%；出生机位至少能读到 2 种媒体尺度，不能只有广场屏。
- **媒体构造**：屏体凹入 0.3–0.5m，边框 / 回壁 0.15–0.25m，结构竖梃每 3–4m 一道；主屏下沿 ≥3.5m，裙楼色带按层高压低但不低于 2.2m，或有雨棚 / 防撞构造；近看不能是浮贴平面。
- **V4 夜景预设**：黑剪影在 Bloom / 反射关闭时仍成立；雾不吞 T-03；CRT 可关闭且扫描线不随 DPR 摩尔纹；机能贴片 8–12 张，不用 15–25 张独立贴图；不显示写死帧时间或 WebGPU 标识。
- **建筑扩建**：首轮 4–8 栋中景 + 一组远景实例；每栋有 entityId、风格族、冠顶、媒体槽、碰撞和 LOD；不遮挡 E-01 / T-01 / T-02 / T-03 与出生通路；共享布局、碰撞、材质文件由单一整合负责人合并。
- **材质层级**：任一固定机位内至少能区分 3 个明度层与 2 个粗糙度层。
- **画面统计**：记录设备、画质档、DPR、draw calls、三角面；不以单张截图代替运行验证。
