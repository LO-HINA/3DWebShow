## 问题定位与改动

| 问题 | 原因 | 本轮处理 |
| --- | --- | --- |
| 直腿摆动、步态僵硬 | 每条腿是一整段胶囊，只有髋部旋转；手臂无肘部 | 增加髋→大腿→膝→小腿→踝→脚趾层级，以及肩→肘→前臂层级；保留原外观语言 |
| 脚步与位移不协调 | 步态相位按 `delta*(7.2+speedRatio*3.6)` 推进，未校准每周期行进距离 | 按碰撞修正后的水平路程推进相位，根据实际速度选择慢走与跑步的步幅、支撑比例；支撑脚在世界坐标保持，摆动脚单独前摆 |
| 转弯时脚随身体横滑 | 转向由碰撞前的速度决定，180° 反向首帧可能转动约 55°；双脚直接继承身体旋转 | 改用碰撞后的实际移动方向，最短角度阻尼并限制最大角速度 12rad/s；支撑脚保留世界方向，摆动脚重新落到转向后的站位 |
| 高低帧率下动画节奏不统一 | 在每个物理子步调用动画，部分渲染帧不更新动画，低帧率一帧又更新多次 | 物理子步只记录位移、速度、朝向、累计路程和着地事件；每个渲染帧插值根节点，再调用一次角色动画 |
| 镜头似乎拖延 | 角色根插值与动画更新节奏不一致，容易把脚滑误认为镜头滞后 | 验证相机锚点严格使用插值根节点，不使用骨盆晃动，也不新增位置跟随缓动；固定侧面机位用于隔离镜头影响 |

核心实现是 [gait.ts](../../src/engine/player/gait.ts)、[controller.ts](../../src/engine/player/controller.ts) 和 [avatar.ts](../../src/engine/player/avatar.ts)；本轮早期路径中的 `player.ts` 已在目录迁移时拆分，对应关系见 [PROJECT_STRUCTURE.md](../PROJECT_STRUCTURE.md)。

## 步态与衔接

- 支撑阶段保持落脚位置，后段加入脚踝后蹬与脚趾弯曲；抬脚后以连续曲线前摆，再落地。腿部解析 IK 计算膝关节及脚踝方向，骨盆只在腿长需要时适度让位。
- 轻推摇杆自然慢走，速度提高后进入跑步；键盘默认 6m/s 已属于跑步范围，不能将这一速度的动作标作慢走。录屏慢走段使用 20% 输入幅值，与摇杆轻推相同，不修改生产速度。
- 起步阶段约 0.09s；停止后按两脚状态完成短促收脚，单脚约 0.095s、两脚错开 0.045s。支撑脚不靠整体位置 lerp 拖回。顶墙速度为零时相位停止，收脚后进入待机。
- 骨盆旋转约 0.025rad、躯干反向旋转约 0.04rad，上下运动为毫米级辅助项。主要改善来自关节与脚步轨迹，而不是增加晃动。
- 腾空使用收腿姿态，不继续地面步态；落地根据实际着地事件与下落速度加入不超过 3.5cm 的短暂屈膝吸收。阴影保持在地面。
- “减少动态”保留必要的膝踝步态，仅关闭呼吸、骨盆与躯干的装饰性动态，避免关闭所有走路动画后产生脚滑。

## 正式模型需要提供

建议提供同一骨架、米制尺度、面朝 +Z 的原地动作：

- Idle；左右脚版本的 WalkStart、WalkStop；可循环的慢走和正常 Walk。
- Jog、Run／Sprint，以及相应速度变化与停步动作。
- 左右 90° 和 180° 转身，包含脚底接触信息，供转向混合与落脚校准。
- JumpStart、Air／Fall、LandLight／LandHeavy。

动作应不带根节点 XZ 位移；如素材含 root motion，接入时提取或移除，不能同时由动作与控制器平移。需记录每个步态周期对应的标定路程和脚底接触时段，以实际碰撞速度调整播放与混合。
